# scripts/

**这里是运行版。正本在 [`research-workflow`](https://github.com/crce-ux/research-workflow) 的 `scripts/checks/`**——开发与测试都在那边。

改脚本请改总仓，再同步过来；**不要只改这里**（改了不会回流，两边会岔开）。

| 脚本 | 干什么 | 服务于 |
|---|---|---|
| `check_review.py` | 审稿意见结构机检：审稿建议四档 / 摘要段 / 编号意见 3–8 条 / 每条带位置与要求 / 不端指控不得给作者看 / 密评节须标「不向作者展示」 | §三 意见的结构 · §五 伦理边界 |

## 查哪种体例

**编号直述体**（实际在用的）：稿件编号 / 标题 / 审稿建议 → 一段摘要 → 编号意见 1..N → 给编辑的保密意见（若在）。

**不是** `Summary / MAJOR POINTS / MINOR POINTS` 三段式——那是 SKILL.md §三 记的另一种体例，实测提交稿没用它。

## 会自动跳过的三种文件

| 跳过 | 为什么 |
|---|---|
| 含「备忘录 / 勿提交」的草稿 | 提交稿才有意义 |
| 自述「不向作者展示」的密评 | 文书结构不同——它本身就是那个「推荐」 |
| 非审稿意见文件（方法指南 / 调研报告 / 图表核查） | 目录模式只认**文件名前缀**或 frontmatter `type: 审稿意见` |

跳过的数量与原因都会打印出来，不静默。

## 边界

**脚本只做能自动化的那一半。**

它查**该有的东西在不在**，不查**意见对不对**——方法学判断准不准、这条批评站不站得住，一律语义，必须人工过。

```bash
python scripts/check_review.py <审稿意见.md>
python scripts/check_review.py <期刊审稿/目录>     # 目录模式
```
