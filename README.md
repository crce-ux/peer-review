# peer-review

[![Structure](https://github.com/crce-ux/peer-review/actions/workflows/structure.yml/badge.svg)](https://github.com/crce-ux/peer-review/actions/workflows/structure.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**期刊同行评议的完整流程**——从决定是否接受邀请，到写出可辩护的审稿意见。

---

## 定位

编辑请你做的是「**领域内同行技术把关 + 提供独立判断**」。

**不是替作者重写论文，也不是当执法者。**

---

## 它覆盖什么

| 阶段 | 内容 |
|---|---|
| **接不接** | 24–48 小时内回复；能力 / COI / 时间 / 新颖性四问 |
| **怎么读** | 三遍阅读法：整体扫描 → 方法学深审 → 细节挑错 |
| **怎么审** | 逐章节审查要点，按研究类型分支（RCT / 观察性 / EEG / ML / 系统综述） |
| **怎么写** | Summary + MAJOR + MINOR 结构；中英范例；给编辑的保密意见 |
| **领域核查** | ⭐ **五层生成轴（定义 / 前提 / 测量 / 分析 / 报告）+ 三份样例**——任意医学领域可用 |
| **伦理** | COPE 五项义务；诚信界限；五类常见陷阱 |

---

## 最有价值的部分：领域核查的「轴」

审稿的价值往往就在领域细节上。**别人审不出来的，往往是你恰好懂的。**

但**领域是列不完的**。所以本文不给清单，给**轴**——圈内人才看得出的问题，都落在这五层上：

**① 定义层 · ② 前提层 · ③ 测量层 · ④ 分析层 · ⑤ 报告层**

拿到一个新领域，逐层问一遍，得到的答案就是你所在领域的核查清单：

- **⑤ 报告层**枚举即完备——直接查表（CONSORT / STROBE / PRISMA / STARD / TRIPOD / ARRIVE …）
- **①–④ 领域问题**无法穷举——**用轴生成**

下面三份样例，就是本套轴生成的产物：

| 样例 | 落在哪层 | 硬伤 |
|---|---|---|
| **TRS / 难治性精神分裂** | ① 定义 · ② 前提 | **依从性未评估**——整篇默认患者吃够了药，从没验过 |
| **EEG / 电生理** | ③ 测量 | **组间 trial 数不平衡**——本身就是偏倚，常被当作细节忽略 |
| **机器学习 / 预测建模** | ④ 分析 | **特征选择在全集上做过**——最常见的泄漏点 |

完整轴、报告规范速查表与三份样例见 `references/domain-checklists.md`。

---

## 三条最容易被违反的纪律

1. **诚信疑虑只写进给编辑的保密意见**，不写进给作者的意见。
2. **不给没有依据的偏好**。「我认为应该用 X 方法」不是理由；「该方法在当前设计下的局限是…」才是。
3. **疑似造假不自行调查**——写进保密意见，编辑走 COPE 流程。
